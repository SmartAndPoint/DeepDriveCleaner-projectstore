## Description

The command the user will open `ddc` for the first time: "show me where the space went and what I can get back". Grouping and the JSON contract follow [[adr/rust-core-library-and-cli-with-json-output|Rust core: library + CLI with JSON output]]; activity and selection follow [[adr/cleanup-safety-model-risk-classes-plan-and-confirmation|Cleanup safety model: risk classes, plan and confirmation]].

## Decomposition

- [x] `ddc scan [PATH...] [--data-dir DIR] [--exclude PATH]` (defaults to `$HOME`); roots are canonicalized, nested roots are dropped; progress indicator on stderr only on a TTY
- [x] Project root: the nearest ancestor with `.git` (a directory or a worktree file), not above the scan root, otherwise the manifest's directory; monorepo `node_modules` are grouped under the repository root
- [x] Activity: max mtime over `<gitdir>/index`, `<gitdir>/HEAD` (for a worktree, `gitdir` from the `.git` file), manifests and lock files; no signal — "unknown"
- [x] Each finding has: allocated (`bytes`), shared (`shared_bytes`), frees at least (`private_bytes`; only where clones are expected — uv, pnpm, bun; otherwise the field is absent and the freeable amount ≈ `bytes`), effective removal method (`removal`: `trash` for `rebuildable` downgraded to `review`), activity, project, whether there is a lock file, whether it is selected by default and why not
- [x] Grouping: risk class → category → items by size descending, ties broken by path
- [x] Large files: top 20 files ≥ 500 MB outside findings (including the remainder of `user-data` regions)
- [x] Totals per class; `inaccessible[]` and `full_disk_access` (a read check of `~/Library/Application Support/com.apple.TCC/TCC.db`) with a hint
- [x] `--json`: `schema_version: 1`, `ddc_version`, `generated_at`, `scan_roots`, `full_disk_access`, findings, totals, errors; `schemars` → `docs/scan.schema.json`; `BrokenPipe` handling
- [x] The last scan is saved to `<data-dir>/last-scan.json` atomically (a temp file in the same directory + `rename`) under a shared lock

## Implementation Plan

Route per the `projectstore:planner` plan (section "ddc scan report") on top of the finished scanner and rule catalog; contracts — ADR "Rust core: library + CLI with JSON output" (JSON schema) and ADR "Cleanup safety model: risk classes, plan and confirmation" §3–§5 (activity, selection, lock, data directory).

1. **`model.rs`** — serializable report types (`serde` + `schemars`): `ScanReport { schema_version, ddc_version, generated_at, duration_ms, home, scan_roots, full_disk_access, totals, findings, large_files, inaccessible, errors_total, skipped, skipped_total }`, `Finding { path, rule, category, class, rule_class, removal, bytes, shared_bytes, private_bytes, files, dirs, incomplete, project, age_days, selected, not_selected, notes, hint, dev, ino }`, `Totals` per class (`bytes`, `private_bytes`, `count`, `selected_bytes`). Paths are absolute; `~` only in CLI output.
2. **`report/project.rs`** — project activity: max mtime over `<gitdir>/index` and `<gitdir>/HEAD` (for a worktree — `gitdir:` from the `.git` file), manifests and lock files of the project root; no signals — "unknown".
3. **`report/mod.rs`** — `scan(env, opts, progress) -> ScanReport`: walk with `RuleVisitor` → `classify` → activity and default selection (`safe` — yes; `rebuildable` — only with known activity ≥ `min_age`, otherwise a reason; `review`/`user-data` — no) → large files (top 20 ≥ 500 MB outside findings and in the remainder of regions, collected by the visitor) → totals → `full_disk_access` (reading `~/Library/Application Support/com.apple.TCC/TCC.db`) and `inaccessible[]` (access errors). Deterministic sort: class → size ↓ → path.
4. **`store.rs`** — `<data-dir>/lock` (`File::lock_shared` for scan, `lock` for cleanup), atomic write of `last-scan.json` (temp file in the same directory + `sync_all` + `rename`).
5. **`docs/scan.schema.json`** — generated by `schemars`; a test compares the committed file with the generated one (`DDC_UPDATE_SCHEMA=1` overwrites it).
6. **CLI `ddc scan [PATH…] [--json] [--data-dir DIR] [--exclude PATH…] [--min-age DAYS]`** — progress indicator on stderr only on a TTY; human-readable output: total per class, then class → category → findings by size descending (activity, "frees ≥", reason for not selecting), large files, Full Disk Access hint; no color with `NO_COLOR`/non-TTY; `--json` with `BrokenPipe` handling.
7. **Tests** — `crates/ddc-core/tests/report.rs` (findings, classes, projects, worktree activity, unknown activity, determinism, large files, schema), `crates/ddc-cli/tests/scan_cli.rs` (temporary `HOME`/`--data-dir`, `--json`, `last-scan.json` without temp files, output order).
8. **Measurement** on the reference machine: `ddc scan ~` and `ddc scan ~/Projects`, median of three after warm-up.

Files touched: `crates/ddc-core/{Cargo.toml,src/model.rs,src/report/,src/store.rs,src/rules/visitor.rs,tests/report.rs}`, `crates/ddc-cli/{Cargo.toml,src/cli.rs,src/cmd/scan.rs,src/render.rs,src/progress.rs,tests/scan_cli.rs}`, `docs/scan.schema.json`, `Cargo.toml`.

## Final Summary

**What was done.** `ddc scan [PATH...]` builds a `ScanReport` (`crates/ddc-core/src/report/`, `model.rs`): findings with class, category, allocated (`bytes`), shared (`shared_bytes`) and — where APFS clones are expected — private size (`private_bytes`), effective removal method (`removal`), project, activity, lock file, default selection and the reason it is absent (`not_selected`). The project root is the nearest `.git` not above the scan root (a `.git` exactly at `$HOME` is not treated as a project), otherwise the manifest's directory; activity is the max over the project root and the artifact's parent (`gitdir/index`, `HEAD`, manifests, lock files). Large files outside findings (including `.app` bundles and the remainder of `~/Downloads`), `inaccessible[]`, `skipped[]`, `full_disk_access`. `--json` with `schema_version: 1`; the schema is generated by `schemars` into `docs/scan.schema.json`. Human-readable output groups class → category → findings by size descending, shows totals per class and "Can free now … frees ~". The last scan is saved to `<data-dir>/last-scan.json` atomically under a shared lock (`store.rs`; `rust-version` raised to 1.89 for `File::try_lock`).

**Why.** The report is the contract for the background scan, `ddc clean` and a future GUI (ADR "Rust core: library + CLI with JSON output"): a strict schema versioning policy, a deterministic order, and the "frees" total is honestly marked as an estimate.

**Tests.** `make check` — 107 tests, fmt and clippy clean (2026-10-17). For this story: `crates/ddc-core/tests/report.rs` (13), `crates/ddc-cli/tests/scan_cli.rs` (3). `projectstore:reviewer` review: blockers (activity with a stale git root, weak AC1 test) fixed and covered by tests.

**Measurement on the reference machine (2026-10-17).** `ddc scan ~`: median 37.0 s; 5.5 million files, 544.8 GiB; `safe` 1919 findings / 76.3 GiB, `rebuildable` 126 / 35.1 GiB (24.4 GiB selected), `review` 263 / 79.4 GiB, `user-data` 11 / 114.1 GiB; selected by default 100.6 GiB, frees ~88.6 GiB. `ddc scan ~/Projects`: median 10.2 s.

**Risks and follow-up.** The "frees" total is an estimate: it is understated if both sides of a clone are selected, and overstated where clones are not measured. Schema consumers (GUI) must reject an unknown `schema_version`. Human-readable output for `ddc clean` shows only `~`; the `≥` on a finding appears only in `ddc scan`.

## Technical Notes

- Directory mtime is unreliable (it changes whenever any file is created), so activity comes only from the signals listed.
- Output: terminal width, no colors with `NO_COLOR` or non-TTY; paths are shortened to `~` only on output.
